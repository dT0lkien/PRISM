# Prism

VPN-клиент для Windows на ядре **sing-box 1.13.15** с упором на гибкую маршрутизацию:
TUN и системный прокси, правила по приложениям, доменам, IP и портам.

Готовые сборки лежат в `dist/`:

| Файл | Что это |
|---|---|
| `Prism-<версия>-x64.exe` | Установщик (NSIS). Можно менять папку, создаёт ярлыки. |
| `Prism-<версия>-portable.exe` | Портативная версия — один файл, ничего не устанавливает. |

Сборки **не подписаны сертификатом**, поэтому при первом запуске Windows покажет
SmartScreen: «Подробнее» → «Выполнить в любом случае».

## Как это работает

### Два способа перехвата

**TUN** — создаётся виртуальный сетевой адаптер, ядро забирает **весь** трафик системы,
включая UDP. Это единственный режим, в котором работает голос в Discord и играх.
Требует прав администратора: Windows не даёт создавать адаптеры обычным процессам.
При первом включении Prism предложит перезапуститься с UAC.

**Системный прокси** — прописывается в настройках Windows (`127.0.0.1:2080`), прав не
требует. Ловит только те программы, которые системный прокси учитывают, и **не передаёт
UDP**. Годится для браузеров, не годится для голоса.

Локальный порт SOCKS5/HTTP (по умолчанию 2080) открыт **всегда**, в обоих режимах —
его можно прописать вручную в любой программе, которая умеет прокси.

### Порядок правил

Побеждает первое сработавшее сверху вниз:

1. Служебное: определение протокола, перехват DNS
2. Локальная сеть → напрямую *(если включено)*
3. Блокировка QUIC *(если включена)*
4. **Правила по приложениям** — вкладка «Приложения»
5. **Свои правила** — вкладка «Маршруты», порядок меняется перетаскиванием
6. **Пресеты** — сначала блокировки, потом фиксы, потом «через VPN», потом обходы
7. Режим маршрутизации с главной страницы

Режимы: **Умный** (РФ и игры напрямую, остальное в туннель), **Через VPN** (всё в туннель),
**Список** (всё напрямую, в туннель только явно указанное), **Напрямую** (туннель поднят, но не используется).

### Про Discord

Discord ломается по трём причинам, и Prism закрывает все три:

1. **Голос идёт по UDP** на порты 50000–65535 к серверам `*.discord.media`. Системный прокси
   UDP не передаёт вообще — отсюда вечное «RTC Connecting». Нужен режим **TUN**.
2. **Провайдер подменяет DNS-ответы** для доменов Discord. Пресет «Discord Fix» разрешает
   их отдельным DNS через прокси.
3. **Картинки и вложения ходят по QUIC** (UDP/443), который часто режется. Настройка
   «Блокировать QUIC» роняет UDP/443, браузер и Discord откатываются на TCP — и всё грузится.
   Голосовые порты при этом не трогаются.

Пресет «Discord Fix» заворачивает в туннель целиком процессы `Discord.exe`, `DiscordPTB.exe`,
`DiscordCanary.exe`, `DiscordDevelopment.exe`, `Update.exe` — то есть весь трафик приложения,
а не только совпавшие домены.

Если голос всё равно не поднимается — почти всегда виноват сервер: не все VPN-серверы
пропускают UDP. Проверить можно на вкладке «Соединения»: если строки с `discord.media`
и протоколом UDP появляются, но трафика по ним нет — проблема на стороне сервера.

### Списки маршрутизации

43 набора правил (geosite/geoip) **вшиты в приложение** — российские домены, банки,
госуслуги, Discord, Telegram, YouTube, игровые сервисы, реклама и прочее. Ничего не
скачивается при старте, поэтому VPN поднимается даже когда GitHub недоступен.

## Форматы, которые понимает импорт

Ссылки: `vless://`, `vmess://` (base64-JSON и URI), `trojan://`, `ss://` (SIP002 и legacy),
`hysteria2://` / `hy2://`, `tuic://`, `anytls://`, `socks5://`, `http(s)://`.

Подписки: список ссылок, base64 от списка, **Clash YAML**, **sing-box JSON**.
Формат определяется автоматически. Подписки обновляются раз в 12 часов, выбранный
сервер при этом сохраняется.

## Разработка

```bash
npm install
npm run setup        # скачивает ядро sing-box и wintun в resources/core
npm run dev          # запуск в режиме разработки
npm run build        # сборка renderer + main
npm run pack:win     # сборка .exe (установщик + портативная)
npm run icons        # перегенерация иконок
```

`npm run setup` обязателен после клонирования: бинарники ядра (около 100 МБ)
в репозитории не хранятся, чтобы не оседать в истории git. Скрипт качает их
с GitHub-релизов sing-box и с wintun.net, версии зафиксированы в
`scripts/fetch-resources.mjs`. Флаг `--rules` заодно обновит списки маршрутизации.

Проверки:

```bash
node scripts/run-validate.mjs
```

Прогоняет генератор конфига через настоящий `sing-box check`: все сочетания режимов,
все протоколы ссылок, все 43 набора правил — 35 проверок.

```bash
node scripts/run-store-test.mjs
```

Проверяет живучесть хранилища: порча файла настроек не должна стоить пользователю
серверов — данные достаются из резервной копии, битый файл сохраняется для разбора.

```bash
node scripts/run-e2e.mjs
```

Сквозной тест: поднимает локальный shadowsocks-сервер тем же ядром, запускает через него
Prism и проверяет, что HTTP реально ходит, счётчики трафика тикают, Clash API отвечает,
узел переключается и порт освобождается после остановки — 16 проверок.

```bash
npx electron scripts/shoot.mjs
```

Снимает скриншоты всех экранов в `shots/` с подставными данными.

### Структура

```
src/
  shared/           общий код main и renderer
    types.ts          модель данных
    parsers.ts        разбор ссылок и Clash-конфигов
    config-builder.ts сборка конфига sing-box    ← сердце маршрутизации
    presets.ts        пресеты, в т.ч. Discord Fix
    rulesets.ts       реестр вшитых geosite/geoip
  main/             процесс Electron
    core.ts           жизненный цикл ядра, падения, перезапуск
    clash.ts          Clash API: трафик, логи, соединения
    win.ts            UAC, системный прокси, автозапуск, список процессов
    subs.ts           загрузка и слияние подписок
  renderer/         интерфейс на React
resources/
  core/win/         sing-box.exe, wintun.dll, libcronet.dll
  rules/            43 файла .srs
```

`resources/core/mac/sing-box` нужен только для тестов на macOS, в Windows-сборку не попадает.

### Заметки по реализации

- **Системный прокси ставит само приложение**, а не ядро. Так его гарантированно
  снимут при выходе или падении ядра — иначе пользователь остался бы без интернета
  с прописанным мёртвым прокси. Прежние настройки сохраняются и восстанавливаются.
- **Зависшие процессы ядра отстреливаются по пути к своему бинарнику и конфигу**,
  а не по имени `sing-box.exe` — иначе Prism убивал бы ядро соседних клиентов
  (Hiddify, Nekoray и др. тоже носят sing-box). Windows не убивает дочерние процессы
  вместе с родителем, поэтому ядро может пережить падение или выключение и держать
  TUN-адаптер — выглядит это как «пропал интернет». Такие хвосты снимаются при
  следующем запуске, а на `session-end` уборка идёт синхронно: система не ждёт промисов.
- **У файла настроек есть резервная копия.** Если основной повреждён, данные берутся
  из неё, а битый файл сохраняется рядом, а не затирается молча.
- **DNS-сервер «напрямую» идёт без `detour`**: ядро отказывается стартовать с
  `detour` на пустой direct-outbound.
- **Смена сервера не перезапускает ядро** — используется селектор через Clash API,
  соединения не рвутся. Перезапуск нужен только при смене настроек маршрутизации.
- Если один сервер в списке кривой и ломает весь конфиг, Prism повторяет запуск
  только с активным сервером и пишет об этом в журнал.

## Обновления

Установленная версия обновляет себя сама через релизы GitHub (`electron-updater`).
Раз в шесть часов приложение проверяет, не вышла ли новая версия, и предлагает её
поставить. **Скачивание не начинается без согласия пользователя** — у клиента VPN
это может быть мобильный интернет, а установщик весит около 100 МБ.

Перед перезапуском в установщик Prism останавливает ядро и возвращает системный
прокси в исходное состояние, иначе пользователь остался бы без интернета с мёртвым
прокси в реестре.

Портативная сборка обновляться не умеет — в интерфейсе для неё показывается
ссылка на страницу релизов. Обновление отключается на вкладке «Настройки».

Технически: `publish` в `electron-builder.yml` заставляет сборщик положить рядом
`latest.yml` и `app-update.yml`; workflow прикладывает `latest.yml` к релизу —
без него обновление не найдёт новую версию.

## Лицензии

Ядро **sing-box** распространяется под **GPL-3.0-or-later**, драйвер **wintun** — под
своей лицензией. Их тексты кладутся рядом с бинарниками (`resources/core/win/LICENSE-*.txt`)
и попадают в установщик — это требование GPL при распространении сборки.

Prism запускает ядро отдельным процессом и общается с ним через CLI и HTTP, не линкуясь
с ним, поэтому код самого приложения GPL не наследует. Если хочется исключить любые
вопросы — проще всего выпустить проект тоже под GPL-3.0.

## Автосборка

`.github/workflows/build.yml` на каждый push собирает проект **на настоящей Windows**
(`windows-latest`) и кладёт `.exe` в артефакты, а на Ubuntu прогоняет проверки конфигов
и сквозной тест трафика. Тег вида `v1.0.0` дополнительно создаёт GitHub Release с файлами.

## Что не проверено

Сборка делалась на macOS, поэтому **на живой Windows приложение не запускалось**.
Проверено: генерация конфигов настоящим `sing-box check`, сквозной прогон трафика через
ядро, целостность exe и вшитых иконок, отрисовка всех экранов. Windows-специфичные пути —
создание TUN-адаптера, UAC-элевация, запись системного прокси в реестр, задача автозапуска
в планировщике — написаны, но вживую не прогонялись.
